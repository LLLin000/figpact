# G7 计划（收敛版）：从研究型引擎到可发布的科研绘图工具

**基线**：`master` @ `c133673`（2026-10-15 核对）。
**定位**：本文是 G7 的**唯一活计划**。`docs/G6B_FINAL_ADJUDICATIONS.md` §七 保留 G6b 收口时的原始裁定记录；`docs/G7_PLAN.md` 的**上一版**（含 plate 体系、`locked/bounded/free` 三档策略、check/apply/proof 命令面、O1–O4 四件输出）**已作废**，其有效部分在本版"阶段 C"中缩为"先审计、后最小修改"。
**依据**：仓库源码核对、`docs/research/R1–R6`（每条事实带 URL）、评审修正（2026-10-15，用户提交）。
**不做完成度百分比估计**：底层引擎完成度与陌生用户可用度是两个不同指标，本计划只用"阶段结束条件"表述进度。

---

## 1. 最终结论

保留现有技术架构，**停止扩展产品范围**，只围绕两个用户痛点开发，并完成一次必要的工程化收尾。

- **痛点一**：Python 科研图的细节修改困难 → 用户能选中标注、拖动、真实验证、**保存到原始文件**，下次重新运行脚本仍然保留修改。
- **痛点二**：不同尺寸的小图最终投稿字号/线宽不统一 → 用户指定每张小图的**最终宽度**与共同样式规格，系统**从原始 Python 图重新渲染**（不是事后缩放 PDF）。

**两个痛点之外，暂不主动扩展。** 目标态：一个第一次使用 figpact 的科研人员，能打开自己的 Matplotlib 图、移动一个受支持的标注并保存；随后把两张图按最终尺寸统一规格，而无需反复改 Python 试参数。

### 阶段与顺序

| 阶段 | 工作 | 结束条件 |
|---|---|---|
| **A** 稳定性 | P1.5 源文件修订误拒 | 真实变化必拒、无变化不误拒（各有真实反例） |
| **B** 编辑闭环 | 候选 → 授权 → 持久保存 → 重启复现 | NMR 真实标注完整闭环成功 |
| **C** 最终规格 | C1 只读审计 → C2 最小受控修改 | NMR/FTIR 实现目标规格或精确报告不可行 |
| **D** 发布包装 | wheel、包内资源、薄 CLI、README、许可证 | 脱离源码目录可安装使用 |
| **E** 小规模试用 | 陌生脚本与新用户测试 | 主要阻断可解释，无错误科学修改 |

**明确不做**：新 PDF 引擎、整图自动排版、通用 Python AST 编辑器、大型 plate 子系统、G6b 规模的新评测。
**并行约束**：开发 Agent 可并行写测试与代码，但**不建议多个 Agent 同时重构同一条写入链**。

## 3. 阶段 A：P1.5 源文件误拒（P0，先修）

**目标**：修复可信性，不增加功能。误拒应被消除，真实变化必须继续被拒绝。

### 3.1 不可妥协的设计

> **评估前冻结受保护输入的身份，评估后复核同一组输入**；不能因为重建期间发生过修改就默认重试，**更不能删除复核**。

| 修改点 | 应该做 | 不应该做 |
|---|---|---|
| 源身份 | 以**文件内容 SHA-256** 为内容版本依据 | 继续把 `mtime_ns` 当内容身份 |
| 文件集合 | 在动作**开始前**冻结已声明的依赖与输出分类 | 动作后重新扫描出另一套规则再比较 |
| 产物排除 | 精确排除**声明的产物、工作目录与可识别的运行时临时文件** | 简单忽略所有 `.png`/`.csv`/`.pdf` |
| 重建后复核 | 判断**受保护输入**是否真的变化 | 直接删除 `_rebuild()` 后的安全检查 |
| 检测到变化 | 拒绝候选并**指出变化来源** | 自动重拖、静默重试并覆盖外部修改 |

**两条必须写进实现的红线**：
1. **不得按后缀排除**：科研图的 PNG/CSV 完全可能是**科学输入**，不能因为该类型也常作输出就排除在科学保护之外。
2. **冻结清单不等于可以漏检新依赖**：既有受保护输入按冻结的内容身份复核；若构建过程可能引入**新的**代码依赖或科学输入，必须通过依赖声明或"受保护集合变化"检测明确处理，**不能让冻结机制变成漏检机制**。

**已定位的误判通道**（行号见 `docs/research/R4_revision_tracking.md`）：M1 mtime 指纹 `!=` 判定；M2 含 `mtime_ns` 的整字典比较；M3 合法生成物进入指纹；M4 排除集取"此刻的"集合；M7 判定发生在 `_rebuild()` 之后。

### 3.2 完成标准（永久回归反例）

| 反例 | 期望 |
|---|---|
| 源文件只被 `touch`，内容未变 | **不拒绝** |
| 源文件同大小、同时间戳、内容被改 | **必须拒绝** |
| 重建产生合法缓存/临时文件/导出产物 | **不误拒** |
| 重建期间外部修改 Python 或科学输入 | **必须拒绝** |
| NMR、FTIR 同进程多次正常构图 | **零虚假 `STALE_REVISION`** |
| 既有 G3 History、G5b CAS 与独立验证语义 | **保持不变** |

**结束条件**：不是"测试全绿"，而是**误拒与漏拒分别有真实反例证明**。完成后不再优化指纹扫描耗时，也不顺带重写运行时。

## 4. 阶段 B：拖动后真正保存（P0，核心痛点一）

### 4.1 用户旅程

1. **直接拖动**：图元实时显示毫米读数；松手仅产生**一次**正式 evaluate。
2. **选择保留**：验证通过的候选进入**待保存修改集合**；用户可继续改其他标注。
3. **点击"保存修改"**：显示**准确的目标文件、参数变更与源码差异**，由用户确认这一次写入。
4. **提交并重新验证**：复用既有写入模块，完成 CAS、Journal、磁盘核对与独立重建。
5. **重开仍成立**：新会话从真实文件重建，位置、科学内容与此前批准的修改保持一致。

### 4.2 关键决定：不新增保存引擎（只加薄协调层）

现状缺口（已核查）：`IntentSession` 保存的是会话内已接受操作，而 `SessionHub.create_plan` 主要为 Python Native `LAYOUT_MM` 与当前受支持的作者化结构生成写入计划；两者**尚未接通为通用保存路径**。

新增一层很薄的 `SaveAcceptedChanges` 协调逻辑，**只负责把已接受候选转换成既有写入 API 的数据形状**：

| 来源 | 写入策略 |
|---|---|
| YAML 受控参数 | 汇总已接受参数的最终值，用既有 YAML 精确补丁生成修改，再走既有 CAS/Journal |
| Python `LAYOUT_MM` | 复用 `python_native.plan_layout_edit`，仅处理受支持的唯一绑定 |
| 无绑定但符合作者化白名单 | 走既有 Authoring 路径，**要求显式确认** |
| 绑定歧义 / 跨 scope / 无法证明安全 | **拒绝并说明原因** |

**不做**：`source_writer_v2`；Inspector 自己改 Python AST。

### 4.3 两条安全约束

1. **保留双状态**（P0a）：

| 源码写入 | 图形验证 | 页面显示 |
|---|---|---|
| 未写入 | 未运行 | 有待保存修改 |
| 已提交 | 通过 | 修改已保存并通过验证 |
| 已提交 | 失败 | 源码已写入，但图形验证失败 |
| 拒绝或取消 | 未运行 | 原文件未修改 |

   验证失败后**不能**凭空说源码未修改；恢复用既有 Journal，并核对当前文件版本。

2. **原子替换 ≠ 元数据全部保持**：`source_writes._write_target()` 建临时文件后 `os.replace()` —— 需补**原文件权限等属性的跨平台回归检查**（POSIX 上新临时文件的权限不一定等于被替换文件）。且**单文件原子替换不得被宣传为多文件操作的整体原子性**。

### 4.4 唯一验收（NMR 全旅程）

> 选择 3.91 ppm 标注 → 上移 0.15 mm → 引线标签端跟随、科学峰锚点固定 → 接受并保存 → 关闭服务 → **再次运行原脚本**。

必须同时成立：最终位移满足声明的测量容差；科学指纹不变、非授权对象无违规移动；真实配置或源码已落盘；重启后重建结果一致；外部修改文件、拒绝授权、取消操作的反例全部受控。

## 5. 阶段 C：Final-size Style（P1，核心痛点二）

**最大危险不是功能太少，而是**建立第二套与现有 YAML 参数竞争的样式真值**。故分两步。

### 5.1 C1：只读审计（不新增任何源码修改能力）

输入：每图最终宽度（如 NMR 42 mm、FTIR 38 mm）+ 共同目标（轴标题 8 pt、刻度 7 pt、线宽 0.8 pt）。
复用 `scene.py`、`inventory.py`、`units.py`，报告须能回答：

| 指标 | 必须回答 |
|---|---|
| 源文件画布宽度 | 原始尺寸是多少 |
| **真实导出宽度** | 实际 PDF 页面宽度是多少（非声明值） |
| 缩放因子 | 若外部继续缩放，字号如何变化 |
| 字体角色 | 轴标题/刻度/图例/标注各是多少 pt |
| 线宽 | 实际值与目标差多少 |
| 空间约束 | 目标尺寸下有无裁剪或文字重叠风险 |
| 编辑能力 | 哪些字段存在安全修改入口 |

**名义字号与实际占用分开报告**：同样的 8 pt 在不同字体下字高/字宽不同，上下标与数学字体不应机械比较；测量必须在正确完成布局与绘制之后进行（renderer/Figure 尺寸/DPI 都会改变测量结果，陷阱见 R2）。

### 5.2 C2：最小受控修改（第一版只统一三个角色）

| 角色 | NMR 当前 | FTIR 当前 | 目标 |
|---|---|---|---|
| `axis.title` | 8.5 pt | 8.5 pt | 8 pt |
| `axis.tick` | 8.0 pt | 8.0 pt | 7 pt |
| `curve.linewidth` | 0.75 pt | 0.85 pt | 0.8 pt |

这些参数**已在真实配置中存在**。FTIR 官能团标注 4.7 pt、NMR 峰标注 6.0 pt 第一版**只检查、报告，不默认强制统一**——它们虽同名 annotation，信息密度不同，强行统一可能让 FTIR 放不下。
**期刊规则不写成全局常数**：选 Nature 风格则按 Nature 规范检查小字号，但该规则**不对所有期刊强制生效**。

### 5.3 不要混用两种缩放模型

- **模式 A（诊断）**：`f_final = f_source × W_target / W_export` ——仅用于诊断"外部缩放过"造成的字号变化。
- **模式 B（实现）**：直接按最终物理尺寸重新渲染 ——目标是 8 pt 就把按最终尺寸重绘的图设为 8 pt；**不应再乘旧图宽度比例，也不应再用 48 mm 画布补偿一次**。

**重新渲染以满足最终规格，与对现有导出文件计算缩放补偿，是两种不同模式，不能叠加。** figpact 优先实现 **模式 B**，模式 A 作为只读诊断。
另：`bbox_inches='tight'` 会让页面尺寸随内容变化 → **必须实测导出尺寸**，不能把配置尺寸当出版尺寸。

### 5.4 空间不足时的正确输出

不得为凑 38 mm 而擅改科学视口、压低字号或裁掉谱线。正确结果是**明确的不可行报告**：

> **当前规格不可行** —— FTIR 目标 38 mm 宽度下，一项峰标注与相邻对象冲突。当前字号目标未被自动改变。可选：增加图宽 / 调整标注位置 / 明确重新指定局部字号。不得自动修改科学数据。

报告需含冲突对象 **GID**、实际位置与**测得的超限量**。"明确告诉用户放不下"是**一次正确的系统结果**，不是失败。

### 5.5 第一版结束标准

两张真实图能：① 从各自源码确定受支持的样式参数；② 在指定最终物理尺寸下重新构图；③ 实测导出尺寸、字号、线宽；④ 保持受保护科学内容与视口语义；⑤ 对放不下的内容给出明确不可行报告；⑥ 分别导出供 Illustrator / PPT / Inkscape 拼版用的矢量文件。
**不需要**：整图自动排版、`figure.gap_mm`、第一版生成合成 Figure（需要预览时可把两图按实际相对尺寸并排显示，但**不为此发展新的出版编译链**）。

## 9. 验收指标与发布状态

**三个最终验收指标**（比"支持多少种 Python 语法/新增多少模块/单测数量"更能反映进步）：
1. **完成一次标注微调需要多少人工操作？** —— 从选中标签到重跑脚本结果一致，中间是否还需理解 YAML、GID、Python AST。
2. **统一两张科研图的最终规格需要改多少次原始代码？** —— 理想：用户只声明每张图最终尺寸与共同样式，系统执行合法修改；不可行时说明原因。
3. **不支持的任务能否清楚解释为什么？** —— 不允许编辑 / 没有绑定 / 需要作者化 / 科学检查不通过 / 文件版本漂移，应有**不同且可理解**的提示。

**两种发布状态，不合并**：

| 状态 | 含义 | 条件 |
|---|---|---|
| **G7 Functional Complete**（内部功能完成） | 三项（P1.5、保存闭环、Final-size Style）均有实际回归证据；仍允许只在源码工作区运行 | 回归证据齐备 |

## 11. 首个开发任务：**G7-A / P1.5 源修订误拒修复**

**实现约束**
1. 以**内容哈希**为输入内容身份的权威依据，不用 `mtime_ns` 或文件大小代替内容验证。
2. 重建前建立明确的**受保护输入快照**，冻结已声明输入与合法产物的分类；重建后按**相同**受保护身份复核。
3. **不得**因后缀相同就排除可能的科学输入；新增依赖或受保护集合变化**不得静默漏检**。
4. 不删除真正的 TOCTOU 检测；不新增自动重拖或静默重试前端兜底。
5. 不修改科学 QA、目标位移 Oracle、G3b Journal、G5b 写入授权语义。
6. 复用当前功能与数据结构，**不新建**一套源修订或构建缓存框架。

**回归测试**：§3.2 的六条反例全部覆盖。

**交付证据**：最小源码 diff；对应测试与执行结果；原误拒的**复现与修复前后对照**；能证明**未降低真实变更检测敏感度**的反例。
