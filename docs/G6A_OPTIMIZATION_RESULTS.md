## 2. 机制与不变量

### 2.1 优化 1：来源指纹一次检查内去重（`figpact/intents.py`，commit `7d581b1`）

**机制**：`_source_evidence` 在**单次调用内**按 resolved path 记忆 `_file_record` 的结果；这个
记忆是**函数局部 dict**，**没有跨调用缓存**——下一次公开调用照样从零重算。持久化前的
stale-source 真实字节复核未变。`contracts.py` 里没有哈希逻辑，故未动。

**为什么会有重复**：12 个重复的来源是**声明式科学输入**，它们位于**脚本目录内**：目录遍历
（`rglob`）已经把它们哈希过一遍，随后 `required` 循环又把同样 12 个路径哈希了第二次。解析后的
路径字符串完全相同 → dict 键相同 → 第二次哈希覆盖第一次，**语义无变化、纯浪费**。被重复读的
正是 Bruker 的 `acqus` / `1r` / `procs` 等大文件，合计 **830,178 B**。现在每个路径在一次调用内
只哈希一次。

**不变量**：
- 文件集合、解析方式、域外排除规则**未变**，只去掉同一路径的第二次哈希；
- 无跨调用/跨会话缓存，因此不会把上一轮的陈旧字节当成事实；
- 语义不变（`STALE_REVISION` / `SOURCE_CHANGED` / `EVIDENCE_INCOMPLETE` 等判定路径未改）。

### 2.2 优化 2：`_clip_polyline_runs` 框内快路径（`figpact/scene.py`，commit `aa0f7ca`）

**机制**：仅当**整条有限折线**可证明**完全落在裁剪框内**时短路。此时 Liang–Barsky 的参数恒为
`t0=0.0` / `t1=1.0`，同一串 IEEE 双精度运算用 Python float 照算，因此输出**逐位一致**。资格判定
的裕度按舍入上界推导（`2**-45` 尺度 × 64 倍余量），左/下边可含等号、右/上边加守卫。

**明确不走快路径的情形**（一律回到旧路径）：NaN 断口、非有限点、退化折线、单点、以及**任何
部分裁剪**。旧路径**逐字未改**。

**本轮未做的事**（防夸大）：未向量化 Liang–Barsky，未改浮点运算顺序，未新增近似/容差型判定。

**不变量**：
- 快路径只在"可证明全内"时触发，且用与旧路径同序的浮点运算；
- 部分裁剪与所有退化输入的行为由未改动的旧路径决定；
- 输出的 runs / points 结构与旧实现完全相同（见 §3.2）。

### 3.3 `frame_revision` 变化原因的精确说明

**同进程互换新旧实现**（顺序 `new / old / new2 / old2`）跑四次 `evaluate`：`scene_json` **逐字节
相同**——`scene_sha256` `1502f093…`、`frame_revision` `ba3ad199…`、`png_sha256` `110ff6ce…`
四次一致。

**跨代码编辑时 `frame_revision` 会变，原因只有一个**：`frame_revision` 里包含
`source_revision = engine_fingerprint over figpact/**`。把该指纹**换成假值**后重跑，diff **恰好
只有 `source_revision` 一行**，`nodes` 与 `png` **完全相同**——机制已由此证明，不是臆测。

**行为字段前后完全相同**（两次实现、两个 commit 都一样）：

| 字段 | 值 |
|---|---|
| `png_sha256` | 相同 |
| `checks_sha256` | 相同 |
| `error_mm` | `3.913536161803677e-15` |
| `measured_delta_mm` | `[0.0, 0.1500000000000039]` |

也就是说：**几何、引线、PNG、QA/科学检查的值一个都没动**；`frame_revision` 的变化纯粹来自
引擎自身源码指纹，属于**预期内的、可解释的**变化，而非科学结果变化。

## 5. 已知代价

- **优化 2 的守卫开销**：不合格的**小**折线需要先付资格判定（守卫）的成本才回落到旧路径。
  小集合微基准上为 **+1% ～ +12%**（两次独立测量）。真实 NMR 图的 15 条折线**全部命中**快路径，
  因此在目标场景**没有**这项代价；该代价只落在"大量小折线且多为部分裁剪"的图上。
- 优化 1 **没有**跨调用缓存，所以同一份证据在两次公开调用之间仍会重算（这是**有意**的：避免
  陈旧字节被当成事实）。它只消除**单次调用内**的重复哈希。
