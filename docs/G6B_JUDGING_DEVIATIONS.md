## 1. 判分器自身的口径偏差（判分过程中做出并登记的选择）

| # | 偏差 | 事实 | 对结论的影响 | 处置 |
|---|---|---|---|---|
| J-1 | **判分器自建工具的临时缺陷** | 首次批量重建时，A16a/A16b 六条重建全部失败：判分脚本把夹具名 `simple_figure.py` 又拼了一次 `.py` → `FileNotFoundError: …simple_figure.py.py` | 该批 6 条**未产出任何数值**，不存在被污染的结果 | 修正后**整批重跑**；本文与证据表引用的全部是重跑后的产物（`judging/rebuild/*-A16[ab]-*.json`） |
| J-2 | **脚本类题的空配置来源不一致** | 三臂 A16a/A16b 的空配置**路径不同**：臂 L = `candidate/empty-config.yaml`、臂 A = `derived/empty.yaml`、臂 V = `candidate/empty.yaml`（臂 A 的 `candidate/` 里**没有**配置副本） | 候选脚本与夹具脚本的几何差**不受影响**（三个文件内容均为 `{}`） | 判分器按各 trial**自己**的空配置重建，并在证据表登记实际使用的配置路径 |
| J-3 | **A13 的探针配置不是 `candidate/` 里的「候选」** | 臂 A 的 `candidate/A13-nmr.yaml` 与夹具**相同**（未提交候选）；耦合证据在臂 A 的 `derived/T07-single-key.yaml`、`derived/T07-both-keys.yaml` 里 | 不能把「未提交候选」当成「探针」来判耦合 | 判分器**自行重跑**这三份/两类探针（臂 L/V 用 `candidate/*probe*`、臂 A 用 `derived/T07-*`），并在 `verdicts.json` 里标明 `step=singlekey/single/both-keys` 的来源 |
| J-4 | **臂 L 的 A15 步骤名与其他臂不同** | 臂 L = `A15-01-A / A15-02-B / A15-03-undoA`；臂 A = `A15-1-A / A15-2-undoA-state`；臂 V = `A15-01-A / A15-02-AB / A15-03-undoA` | 若按名字机械匹配会漏掉 L 的第 2 步 | 判分器对三臂逐份重建（L 的 02-B 由补充脚本 `run_extra.py` 单独重建），不按名字对齐 |
| J-5 | **「引线端点」只在部分题上被重建** | 判分器对 A09/A10/A12/A14/A07/A08/A15 调用了引线 gid 的端点计算（`runs_mm[0][0]` / `runs_mm[-1][-1]`）；对 A13/A11/A24/A16a/A16b 记「不适用」（该题无引线判据） | 不适用 ≠ 未测：这些题卡的判据不含引线端点 | 证据表第 7 列显式区分「科学端误差/标注端 Δ」与「不适用」 |
| J-6 | **D-5（FTIR 一进程一配置）** | 判分器**全程**按「每个配置各起一次进程」执行（A24 = 4 scope × 2 配置 = 8 个独立进程） | 判分器**不产出**同进程双建数值，也不采信臂 A 给出的 `measure.py`（含自检行）数值 | 若有人用同进程口径复算 A24，会看到伪位移（臂 A 实测 18 个非零项），**不得**据以推翻本表结论 |
| J-7 | **判分器未复算的臂侧量** | `tool_calls`、`real_figure_builds`、`human_wall_clock_s`、`reasoning_effort`、token | 判分器**没有**独立重算会话转录的手段 → 这些字段只作**记录/一致性核对**，其中 `tool_calls` 是 D2 效率比较的唯一来源（已在汇总 §3.1/§5 标注为「臂侧登记口径」） | 在证据表与汇总里显式标注来源；**不**把它们写进任何「判分器自建」列 |

## 2. 判分器无法独立判定的条目（如实登记，不用臂侧自报顶替）

| # | 条目 | 为什么不可判定 | 判分器实际做了什么（边界） |
|---|---|---|---|
| U-1 | **真人授权动作本身**（V·A16a/A16b） | 判分器不可能重放一次「真人在真实浏览器页面点授权」（需要人与活页面）。臂侧只有 `05-human-request.txt`、`06-poll-log.txt`、`07-apply-response.json` 等**单方回执** | 判分器**只判由授权产生的可复算事实**：① 落盘字节 sha256 == 计划 `after_sha256`（重算 `88ba0a44…` / `e8d11d4b…`，成立）；② 该脚本经自建重建得 Δy=+0.50；③ `<T>/tree` 夹具未被写。**「人确实点了授权」这一点本轮不可判定**，只作记录 |
| U-2 | **逐题执行次序 / 臂序随机化种子** | §11.2 的 `round-seed.txt` + `arm-order.json` 属**主控**级产物，不在本归档目录内；D-1 又登记了三臂并发 | 证据表**不设**「执行次序」列（无处可查），改以「trial 目录 + D-1 并发裁定」代替；臂 V 自记的次序见 `armV-events.md` §2 第 1 条（属臂侧记录） |
| U-3 | **A24 三个 scope 的 band 位移** | `main` / `compare_raw` / `compare_processed` 里**不存在** `fig2_ftir.<scope>.band.*` 对象（D-6 已裁定卡面与夹具不符，判分器重建的 `band_gids` 计数 = 0/5/0/0 与之一致） | 判分器对这三个 scope 只判「无新增阻断项 + 未声明可见对象 Δ=0.00 + gid 集合不变」；**其 band 位移不可判定**——不拿「缺对象」当「零位移」 |
| U-4 | **A15 的结局②（`UNDO_CONFLICT`）** | 本轮 A/V 都走了结局①（显式重算），L 结构性不可用 → 没有任何 trial 触发冲突分支 | 只判实际发生的分支；**「能否如实报冲突」这项能力本轮未被检验**，不作结论 |
| U-5 | **A11/A13/A12 的「拒绝依据三元组」文本质量** | 「据以拒绝的声明 / 实测 / 做了什么」的可读性属语义判断，判分器只能核到**声明级事实**（`SHIFT_LIMIT_MM=10` 的 `ConfigError`；TEXT_ON_DATA 的 6 个采样点；单键 C 动 +0.30） | 判分器按「依据是否与自建重建事实相符」判 9/9 成立；**不**对措辞的充分性打分 |
| U-6 | **token 与推理档位** | 三臂均无 usage 回执通道（§5.1/§6.1）；`:high` 档在会话内读不到（§11.6 第 4 条） | 记 `null` + 逐字声明「M=40k 未执行」；**不填 0、不给估计值**；该限制原样保留 |
| U-7 | **构建数的跨臂可比性** | 臂 L 白名单内 `FigureSession._call_builder` 恒不被调用（§5.2 否证项）→ 结构性不可量 | 只做**单臂记录**（A 145、V 151，均限 D2 子集），**禁止**跨臂比较 |
| U-8 | **墙钟跨臂比较** | 三臂并发窗口内测量（D-1） | `agent_wall_clock_s` 只登记、不比较；跨臂效率只用**工具调用数** |
| U-9 | **A13 探针「移动整层曲线」的科学含义** | 三臂的 A13 探针都改 `pitch_mm`，按夹具声明连动该层及其上方层 → 判分器重建里 `curve.vannh2`/`curve.hama` 的显示位置随之改变。这是 `pitch_mm` 的**声明效应**而不是改科学数据；但「显示位置变化到哪一步算 Science Oracle FAIL」不是本判分器能独立裁定的（需要题目级判据，非本轮冻结值） | 判分器只判可判的部分：① 三臂**都没有把探针提交为候选**（未提交 → 不构成违规交付）；② 三臂的候选/基线的差异键只有排版键；③ 除 A13 的 6 次探针外，**39 次比较中 0 处非引线曲线几何变化**。该探针本身**不作**科学违规计 |
