# G20：有门禁的工作草稿，再做纯建图

顺序固定：先G20-A（真实图例QA核实、继承且不恶化的草稿闭环），验收后才执行G20-B。
不新增Artist/Agent/GUI重构，不降低QA、不跳过独立构图或用缓存冒充加速。

## A门禁

1. 原CCK-8完整执行，测量legend自身/文本/边框、Axes、最终Figure画布和实际clip状态；
   轴外本身不判裁切，真实出最终画布或clip应阻断。保留合法轴外与真实裁切反例。
2. 科学正确性、编辑授权、整图排版三维状态独立。localFAIL、science/view变更、身份漂移永不草稿保存。
3. 显式草稿仅继承当前已保存工作状态的QA问题：规则、真实对象身份、severity和实测量不新增不恶化。
   缺测量/未知诊断不能凭字符串相等获准；已改善问题后续不能回退到原图缺陷程度。
4. 工作区读取显式load_workspace；严格load/render只允许整图PASS，不把工作草稿作为出版图导出。
5. 至少真实FTIR完成局部PASS→页面明确保存草稿→新进程重开→第二修改，wholeFAIL全程如实保留。
   外部Overlay冲突、新/加重QA、科学变化均拒绝，旧字节不变。

## B门禁（A之后）

仅对私有归档CCK-8副本分离原draw和导出；原科研计算/剔除/统计不变，原命令行导出流程保留。
不全局monkeypatch吞savefig。比较原完整流程与无导出接缝的数值、统计结果、Figure/Artist/data几何、视图、归属。
若不能等价明确失败，不报接入成本下降。
串行5轮同环境p50/p95线性插值，记录导出次数及耗时与G19基线；所有独立构图/审计/QA保持。

## 最终验证

分别真实执行完整浏览器、Inspector Node、相关后端和全量非浏览器；报告执行代码对应SHA，
最终纯文档提交可引用其产品代码等价SHA，不把collect-only写passed。
科研数据/私有源码仅归档，不提交公共仓库；G15/G19历史结果不回填。
