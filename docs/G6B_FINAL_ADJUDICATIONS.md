## 一、三处必须谨慎解释的地方（用户裁定，采纳）

## 二、结论分档（G6b 收口，不再跑新一轮 36 条）

**已独立验证（判分器自建重建）**
- 在本轮冻结任务与判分范围内，vNext 臂 V 完成 **12/12**（D1b），臂 A 10/12、臂 L 9/12。
- A16a/A16b 的目标位移（各 **Δy=+0.5000 mm**，残差 ≤0.01）与科学不变量（gid 集合逐位不变、所有曲线节点几何逐位不变）由**独立重建**支持；**只有臂 V** 具备该路径（臂 L/A 候选脚本与夹具逐字节相同）。
- 未发现**错误接受**（0/12）、**误拒**（0）、**科学违规**（0）；「必须拒绝」9/9 正确。
- 36/36 自建结局与臂侧标签一致 → **无「自报成功而不成立」**。

**已有支持性证据**
- D2 九题上臂侧登记的工具调用合计：V **56** vs L/A **76**（**−26.3%**；中位 6 vs 8/9）。
- 限制：调用数属**臂侧登记**（判分器无法从统一原始调用事件流重算）；**执行次序与臂序种子未随归档**，随机化无法复核；样本规模小（9 题配对）。
- 因此表述为：**在 9 项共同可执行任务上，vNext 的登记工具调用总数较另两臂低约 26%，但尚无可比较的端到端耗时证据**；不是统计意义上的普遍性能提升，也不代表每种任务都减少调用（存在反例：A11、A10/A12/A13）。

**暂不能宣称**
- 普遍提速；广泛 Matplotlib 兼容；任意 Python 脚本的安全编辑；跨宿主的成熟产品体验。
- 现有作者化能力**仅覆盖 `ax.annotate(..., textcoords="offset points")` 这一类结构**。

## 三、下一步：G7「真实科研图编辑工作流」（用户裁定，优先产品化而非继续扩建评测）

| 优先级 | 下一步 | 验收目标 |
|---|---|---|
| P0 | 分离**源码写入状态**与**图形验证状态** | 界面不再把"字节已提交"误表达为"科研图已验证" |
| P1 | 图上直接操作与预览 | 选中标签后拖动/方向键微调/调尺寸；用户不必自己找参数 |
| P1 | 选区 → Agent 复杂排版 | Agent 自动取得 GID/Scene/影响面/约束，用自然语言提修改 |
| P2 | 真实 Python 脚本覆盖 | 评估不同 Matplotlib 写法下的可编辑率、需作者化率、正确拒绝率 |
| P3 | 完整用户流程 profiler | 判断瓶颈在首次加载/交互预览/真实重建/源码保存，再决定是否做 G6a 第三刀 |

**建议的首个产品切片**：点选 NMR 标签 → Inspector 锁定 GID 并显示可编辑能力 → 直接向上拖动（前端即时几何预览与毫米值，拖动期间不逐帧重建）→ 松开后执行真实验证（预览不是成功证据）→ 需要复杂排版时向 Agent 提自然语言要求（共享选区 + 约束）。
R grid 的"相对关系 + 空间预算"可服务于该体验，但**不必先建第二套布局系统**。
