## 〇、收口定性（先给结论）

**G6b 是一次「受控工程验证」，不是严格无偏差、完整可复现的三臂盲测。**

支撑这一定性的已知条件（逐条有据）：三臂并发执行且墙钟不可跨臂比较（D-1）；逐题执行次序与臂序种子未随归档、随机化无法复核（U-2）；臂 L 的工具口径与 A/V 不同质（D-3）；两处题面与夹具不一致（D-4、D-6）；判分工具在 FTIR 上有同进程双建伪影，必须一进程一配置（D-5）；A16a/A16b 的完成链含真人授权且该动作本身不可独立裁定（U-1）；NMR manifest 覆盖率数字缺少可复现的产生过程（本文件 §三缺口 1）。

因此：**不得**把本轮包装成「已证明普遍提速 26%」或「任意科研图都能安全编辑」（红线见 §六）。

## 一、三处必须谨慎解释的地方（用户裁定，采纳）

### ① 「严格正确拒绝 9/12 = 75%」≠ 安全成功率 75%

- **保留**协议预定的严格拒绝率 **9/12**，但必须并列写清三条差额的**实际结局**：A15 在臂 L 是 `structural_unsupported`（白名单无 accept/history），在臂 A/V 是**结局①重算完成**——既非拒绝、**也非误拒**。

- 「必须拒绝的候选 **9/9 均被正确拒绝**」作为**单独结果**列出（A11 越界、A12 碰撞、A13 耦合各 3 臂）。
- A13 需注明其协议允许的**先请示后合法完成**分支（结局①）仍成立，本轮三臂一致选择结局②。

### ② 删除「V 的调用数减少不是靠少建图」这一因果句

- 既然已冻结「构建数不跨臂比较」，该句**无证据支持**（151 与 145 受入口覆盖与计数口径限制），**从正式因果结论中删除**。
- 保留各臂原始构建计数与「不可跨臂比较」的限制说明。
- 该撤回**同时适用于** `docs/G6B_JUDGING_SUMMARY.md` §3.2 的「读法」段与 §6② 的同义句：SUMMARY 顶部已加**显式更正索引**指向本条，**原文保留不覆盖**。

### ③ A24 验证的是「四个 scope 的检查流程」，不是「四个 scope 的标签移动」

- 实测只有 `annotated` 有 band 对象（5 个 `fig2_ftir.annotated.band.*`），另三个 scope 无 band → 该题**能**证明系统不只检查当前 scope、且只改声明键，**不能**证明同一参数在四个 scope 都引起复杂标签布局变化。

## 三、三项证据缺口（逐项登记，不得当作已闭合）

### 缺口 1 — NMR Manifest 覆盖计数（**计数不可复现**）

- 报告写「**18** 棵 NMR 树 × 99 件通过 Manifest」，而 12 题里 NMR 题为 9 道 × 3 臂 = **27 棵**。
- 收口复核（只读，未重跑 trial）：**27 棵全部 `rc=0` / 99 件 OK**（另 1 棵非 trial 的 `_probe` 树同为 `rc=0`）；3 棵 FTIR 树 `rc=0` / 43 件 OK；6 棵纯 Python 夹具树**不适用**（树内无 NMR/FTIR 科学输入）。
- 判分器侧**没有保存**产生「18」的枚举脚本或日志（`judging/_rebuild/*.py` 无 manifest 复核代码；`judging/rebuild/*.json`、`verdicts.json`、`all.json` 无 per-tree manifest 字段）。
- **措辞要求**：引用覆盖率时写「27 棵 NMR trial 树（另 1 棵非 trial 的 `_probe`）**全部通过**」；「18」只能作为**已更正的旧计数**出现，且必须同时给出 `docs/G6B_NMR_MANIFEST_COVERAGE.md`（逐树核对表 + 复现命令 + 追因）。

### 缺口 2 — A16b 实执行 gid ≠ 冻结题面 gid（**D-4**）

- 冻结题面写 `intent.main.label.A`，而 `legacy_plain.py` 的 `FIGURE_ID="legacy"`，实际 gid 为 `legacy.main.label.A`；冻结串零命中、不可执行。
- **措辞要求**：A16b 只能表述为「**按修正后的 GID 完成**」（`legacy.main.label.A`），**不得**称「完全遵循原题面」，也不得把该题当作「题面与夹具一致」的证据。A16a 保持 `intent.main.label.A`（题面与夹具一致）。

### 缺口 3 — 真人授权动作缺独立证据（**U-1**）

- V·A16a / V·A16b 的完成链必须经过 1 名真人在真实页面授权（`human_wall_clock_s` = 80.450 s / 55.231 s，合计 135.681 s，单列、不进 D2）。
- 判分器可复核的只是**授权产生的可复算事实**：落盘字节 sha256 == 计划 `after_sha256`（`88ba0a44…` / `e8d11d4b…`）、该脚本经自建重建得 Δy=+0.50、`<T>/tree` 夹具未被写。
- **措辞要求**：「授权链在浏览器测试中通过」**≠**「这两次正式 trial 的真人动作被独立审计」。不得把 U-1 表述为已闭合，也不得据此宣称写回能力已自动化/稳定。

## 五、实质性证据边界（U-* 逐条引用，作为结论的上限）

- **U-1 真人授权动作本身**：判分器**不可能**重放「真人在真实页面点授权」；臂侧只有单方回执。→ 结论上限：可复算的**授权产物**成立；**授权动作**不可判定（= §三缺口 3）。
- **U-2 逐题执行次序 / 臂序随机化种子**：`round-seed.txt`、`arm-order.json` 属主控级产物、不在归档内，D-1 又登记了并发。→ 结论上限：**削弱严格配对可审计性**；不得宣称随机化已复核。
- **U-9 A13 探针「移动整层曲线」的科学含义**：三臂 A13 探针确实移动了曲线显示几何（`curve.vannh2` / `curve.hama` 随 `pitch_mm` 的声明效应连带移动），但「显示位置变化到哪一步算 Science Oracle FAIL」**未独立裁定**。→ 本轮只能说「**未发现交付产物中的科学违规**」，**不得**扩大为「所有尝试过的候选均已证明科学安全」。
- 其他同样构成本轮上限的条目：**U-3**（A24 三个 scope 无 band 对象 → 其 band 位移不可判定，不拿「缺对象」当「零位移」）；**U-4**（A15 结局② `UNDO_CONFLICT` 本轮无 trial 走到 → 「能否如实报冲突」未检验）；**U-6**（token `null`，`M=40k` 未验证执行；推理档位 `:high` 未独立证明）；**U-7**（构建数跨臂不可比）；**U-8**（墙钟跨臂不可比）；**J-7**（`tool_calls`/`real_figure_builds`/`human_wall_clock_s` 均为臂侧登记量）。

## 六、结论措辞红线（违反即视为超范围声明）

1. **不得**写「已证明普遍提速 26%」或任何单一提速百分比；D2 只能写「在 9 项共同可执行任务上，臂侧登记的**工具调用合计**为 76 / 76 / 56（中位 8 / 9 / 6），反例见 §二」。
2. **不得**写「任意科研图都能安全编辑」；现有作者化能力仅覆盖 `ax.annotate(..., textcoords="offset points")` 一类结构。
3. **不得宣称严格配对随机化或提速**（D-1：三臂并发窗口内测量；U-2：执行次序与臂序种子未归档）。
4. **不得**跨臂比较时间（墙钟）与构建数；构建数只作单臂记录，臂 L 记 `null`（更不得填 0）。
5. 安全性只能表述到「**未发现交付产物中的科学违规**」这一层；**不得**扩大为「所有尝试过的候选均已证明科学安全」（U-9）。
6. 「必须拒绝 9/9」与「错误接受 0/12」只能**限定在受测候选范围内**，不外推。
7. A16b 只能写「**按修正后的 GID 完成**」；不得称完全遵循原题面（D-4）。
8. 引用覆盖率必须写 27 棵（+1 棵 `_probe`）全部通过；「18」只能作为已更正的旧计数出现（§三缺口 1）。
9. **不得**写「树在本轮任何时刻都未被写入」；成立的表述是「**trial 期间**树内写入 = 0」（D-7）。
10. 全篇定性只能是「**受控工程验证**」，不得写成「严格无偏差、完整可复现的三臂盲测」。

| **P1.5** | `IntentSession._guard` 重建后复校源修订的竞态 | 负载下偶发 `STALE_REVISION` 误判（同一 evaluate 纯 HTTP 连打 90 次全 OK；带诊断的全套 9 次全绿 → 与并发/负载相关）。方向：重建前**一次性快照**修订并据此判定，而非重建后再比；**不得**用「过期就重拖」之类前端兜底掩盖（那会破坏「松开恰好一次 evaluate」语义） | G7 P1-a 浏览器套件抖动排查副产物（如实记录，未修） |

**建议的首个产品切片**：点选 NMR 标签 → Inspector 锁定 GID 并显示可编辑能力 → 直接向上拖动（前端即时几何预览与毫米值，拖动期间不逐帧重建）→ 松开后执行真实验证（预览不是成功证据）→ 需要复杂排版时向 Agent 提自然语言要求（共享选区 + 约束）。
R grid 的「相对关系 + 空间预算」可服务于该体验，但**不必先建第二套布局系统**。
